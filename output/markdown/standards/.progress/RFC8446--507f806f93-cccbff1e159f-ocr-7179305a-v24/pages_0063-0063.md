A client that receives a CertificateRequest message without having sent the "post_handshake_auth" extension MUST send an "unexpected_message" fatal alert.

# <u>`4.6.3.  Key and Initialization Vector Update`</u> 

The KeyUpdate handshake message is used to indicate that the sender is updating its sending cryptographic keys.  This message can be sent by either peer after it has sent a Finished message.  Implementations that receive a KeyUpdate message prior to receiving a Finished message MUST terminate the connection with an "unexpected_message" alert.  After sending a KeyUpdate message, the sender SHALL send all its traffic using the next generation of keys, computed as described inSection 7.2.  Upon receiving a KeyUpdate, the receiver MUST update its receiving keys.
