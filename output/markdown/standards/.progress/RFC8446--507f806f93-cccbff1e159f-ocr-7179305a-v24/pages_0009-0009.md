|`Figure 1 below shows the basic full TLS handshake:`|
|`Client                                           Server`|
|`Key  ^ ClientHello`<br>`Exch | + key_share*`<br>`| + signature_algorithms*`<br>`| + psk_key_exchange_modes*`<br>`v + pre_shared_key*       -------->`<br>`ServerHello  ^ Key`<br>`+ key_share*  | Exch`<br>`+ pre_shared_key*  v`<br>`{EncryptedExtensions}  ^  Server`<br>`{CertificateRequest*}  v  Params`<br>`{Certificate*}  ^`<br>`{CertificateVerify*}  | Auth`<br>`{Finished}  v`<br>`<--------  [Application Data*]`<br>`^ {Certificate*}`<br>`Auth | {CertificateVerify*}`<br>`v {Finished}              -------->`<br>`[Application Data]      <------->  [Application Data]`|
|`+  Indicates noteworthy extensions sent in the`<br>`previously noted message.`|
|`*  Indicates optional or situation-dependent`<br>`messages/extensions that are not always sent.`|
|`{} Indicates messages protected using keys`<br>`derived from a[`<br>`sender]_handshake_traffic_secret.`|
|`[] Indicates messages protected using keys`<br>`derived from[`<br>`sender]_application_traffic_secret_N.`|
|`Figure 1: Message Flow for Full TLS Handshake`|
|`The handshake can be thought of as having three phases (indicated in`<br>`the diagram above):`|
|`-  Key Exchange: Establish shared keying material and select the`<br>`cryptographic parameters.  Everything after this phase is`<br>`encrypted.`|
|`-  Server Parameters: Establish other handshake parameters`<br>`(whether the client is authenticated, application-layer protocol`<br>`support, etc.).`|
